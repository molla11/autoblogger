# 웹 UI/UX 개편 기획

2026-10-29. 대상은 `apps/web`의 작업 공간·풀이 기록·타임라인·글 보관함·설정·관리자·에디터 화면이다. 기능·API 계약·데이터 흐름은 바꾸지 않고 화면 구조와 시각 체계만 바꾼다.

## 1. 진단 (1440×900, 샘플 1개 기준)

| 화면 | 문서 높이 | 첫 화면에 보이는 실제 데이터 |
| --- | --- | --- |
| 대시보드 | 1232px | 통계 3개. 프로젝트 목록은 스크롤 아래 |
| 세션 타임라인 | 1450px (사건 6개) | 사건 2개. 실행 출력이 기본으로 펼쳐짐 |
| 연결과 데이터 | 1130px | 카드 4개 중 2개 |
| 프로젝트 상세 | 900px | 세션 0개인데 한 화면을 다 씀 |

문제는 다음과 같다.

1. **크롬이 너무 크다.** 238px 사이드바와 75px 헤더가 함께 있다. 헤더에는 breadcrumb만 있고, 사이드바 하단에는 슬로건 카드가 있다.
2. **같은 소개 문구가 네 번 나온다.** 페이지 제목 슬로건, 280px hero, 사이드바 노트, 하단 온보딩 띠가 모두 같은 내용을 말한다. 실제 데이터는 그 아래로 밀린다.
3. **위계가 뒤집혀 있다.** 장식용 제목은 36px인데 시각·파일명·종료 코드처럼 의미 있는 정보는 8–10px이다. 대비도 2.2:1 정도라 WCAG AA(4.5:1)에 못 미친다.
4. **모든 것이 카드다.** 프로젝트 카드는 184px, 글 카드의 135px 커버는 아이콘과 "01" 번호뿐이다. 목록으로 보여야 할 데이터가 카드 격자로 퍼진다.
5. **타임라인이 사건 수에 비례해 끝없이 길어진다.** 실행 사건은 출력과 함께 기본으로 펼쳐지고, 사건 사이 간격이 30px이다. 실제 세션의 사건은 수십~수백 개다.
6. **자주 쓰지 않는 설정이 앞에 있다.** 프로젝트 상세에서 수집 제외 패턴 입력란이 세션 목록보다 위에 있다.
7. **진행 중 작업 버튼이 내용을 가린다.** 오른쪽 아래에 떠 있는 버튼이 타임라인 사건 위에 겹친다. 헤더 버튼과 기능도 중복된다.
8. **에디터 위에 바가 세 줄이다.** 헤더, 에디터 상단바, 서식 도구 막대 아래 다시 185px 사이드바가 있어 본문 폭이 좁다.

## 2. 목표

- 1440×900에서 대시보드·프로젝트·글 보관함·설정이 **한 화면 안**에 들어온다.
- 세션 타임라인은 사건 수가 늘어도 **사건당 한 줄(약 40px)** 만 늘어난다. 상세는 고정된 오른쪽 패널에서 본다.
- 의미 있는 텍스트는 **최소 12px**, 배지는 11px이다. 보조 텍스트 대비는 4.5:1 이상이다.
- 기존 접근성 이름(버튼·라벨·제목)과 e2e 시나리오는 유지한다.

## 3. 디자인 방향

주제: VS Code에서 알고리즘을 푸는 개발자의 **실험 노트**. 주된 일은 "무엇을 시도했고 어떻게 바뀌었는지"를 훑고 글로 옮기는 것이다. 확장 GUI(사건 목록 + 상세 두 열)와 같은 구조를 웹에도 적용해 두 화면의 사용법을 맞춘다.

- **색**: 기존 초록 정체성은 유지하고, 크림 배경을 차가운 회녹색으로 바꾸고 대비를 높인다.
  - `--bg #F4F6F3` 페이지 · `--surface #FFFFFF` 패널 · `--ink #1C2A23` 본문 · `--ink-2 #46544C` 보조 · `--muted #66736B` 메타(흰 배경 4.9:1) · `--brand #2E5A47` 주요 동작
  - 상태 색: 성공 `#2F7A4F`, 경고 `#8A6116`, 오류 `#B2442F`. 색만으로 구분하지 않고 항상 글자를 함께 쓴다.
- **글꼴**: IBM Plex Sans KR(UI·본문) + IBM Plex Mono(코드·명령·경로·시각). 엔지니어링 문서 계열의 서체가 주제와 맞고, Noto Sans KR보다 세로 메트릭이 작아 밀도가 높다. Mono는 실제 코드·경로·시각에만 쓴다.
- **크기 체계**: 12 메타 / 13 UI 기본 / 14 강조 / 16 섹션 / 20 페이지 제목 / 22 대시보드 제목. 간격은 4의 배수(4·8·12·16·24·32).
- **형태**: 테두리 위주로 하고 그림자는 팝오버·모달에만 쓴다. 모서리는 컨트롤 6px, 패널 8px, 배지 4px로 위계에 따라 다르게 둔다.
- **강조는 한 곳에만**: 타임라인의 세로 레일. 사건 유형을 기호와 색으로 구분하고 시각은 Mono 열로 정렬해 git log처럼 읽히게 한다. 나머지 화면은 조용하게 둔다.
- **제거**: 모든 제목 위의 대문자 eyebrow, hero 일러스트, 장식 커버와 "01" 번호, 사이드바 슬로건 카드, 떠 있는 작업 버튼.

## 4. 화면별 변경

### 앱 셸

```
┌ {} 풀이의 기록 │ 대시보드  풀이 기록  글 보관함 2  연결과 데이터  관리자 ……… ◌ 초안 작성 중 │ (U) ┐  52px, sticky
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- 사이드바와 헤더를 52px 상단 바 하나로 합친다. 콘텐츠 폭이 238px 넓어지고 세로 23px을 되찾는다.
- 진행 중 작업은 상단 바에 스피너와 작업 이름으로 표시한다(항상 보임). 떠 있는 버튼은 없앤다.
- 프로필 메뉴(아바타)에 계정·역할·이번 달 AI 사용량·연결과 데이터·로그아웃을 둔다.
- 960px 이하에서는 "메뉴 열기" 버튼으로 내비게이션을 접는다. 1200px 이하에서는 메뉴 아이콘을 숨겨 폭을 줄인다.
- breadcrumb는 페이지 머리의 "← 상위" 링크로 대체한다.

### 대시보드

```
오늘의 풀이가, 내일의 기록이 되도록.                       [샘플로 둘러보기] [+ 새 프로젝트]
코드에 남지 않은 생각과 시도를 한 편의 글로 이어보세요.
┌ 프로젝트 1 ┬ 보관함의 글 1 ┬ 편집 완료 0 ┬ 공개 0 ┬ 이번 달 AI $0.000 / $15 ━━ ┐   통계 띠 한 줄
┌ 최근 프로젝트 ─────── 모두 보기 ┐ ┌ 최근 글 ────────── 모두 보기 ┐
│ 목록 행 최대 5개                  │ │ 목록 행 최대 5개                 │
└──────────────────────────────────┘ └─────────────────────────────────┘
┌ VS Code에서 기록하기  ① 확장 연결 ② 기록 시작 ③ 통합 터미널에서 실행 ④ 초안 만들기  [연결 안내] ┐
```

- hero·일러스트·통계 카드 3개를 통계 띠 하나로 줄인다. 실제 순서가 있는 내용이라 기록 절차에만 번호를 쓴다.

### 풀이 기록(프로젝트 목록)

- 184px 카드 격자 대신 행 목록(이름·경로·수집 상태)을 쓴다. 행 하나는 약 56px이다.

### 프로젝트 상세

- 제목 줄에 경로·상태 배지·동작(기록 제외 전환·삭제)을 함께 둔다.
- 수집 제외 패턴은 접힌 "수집 제외 패턴 (n개)" 영역으로 옮긴다. 세션 목록이 바로 보인다.
- 세션은 한 줄 행(번호·시작 시각·상태)으로 보여 준다.

### 세션 타임라인

```
← 샘플: 두 수의 합
풀이 세션 3  기록 중                                  [JSON] [기록 중지] [초안 만들기] [🗑]
10월 29일 오후 1:59 시작   파일 1  실행 2  메모 1
[전체 흐름] [sum.cpp]                                              [문제와 제약 ▾]
┌ 사건 목록 (380px, 자체 스크롤) ──┬ 선택한 사건 (sticky) ───────────────────┐
│ 13:53 ◇ 코드 저장   sum.cpp      │ 터미널 실행  sum.cpp  13:54                │
│ 13:54 ▶ 실행  정상 종료  115ms   │ [정상 종료] 종료 코드 0  115ms              │
│ 13:55 ✎ 북마크  "입력 2 3의…"     │ $ g++ sum.cpp -o sum && ./sum             │
│ …                                │ -1                                        │
└──────────────────────────────────┴───────────────────────────────────────────┘
```

- 한 줄 행에 핵심 요약을 담는다. 실행은 상태와 소요 시간, 메모는 첫 줄, 코드 수정은 변경 줄 수를 보여 준다. 펼치지 않아도 흐름을 읽을 수 있다.
- 1000px 이상에서는 목록과 상세를 두 열로 보여 준다. 그보다 좁으면 선택한 행 아래에서 상세가 펼쳐진다.
- 행은 버튼이다. ↑/↓로 이전·다음 사건을 선택하고 포커스를 옮긴다. 두 열에서는 `aria-current`, 펼침 모드에서는 `aria-expanded`로 상태를 노출한다.
- AI 요약 문장 속 `[사건 UUID]` 표기를 "북마크 14:19" 같은 근거 칩으로 바꾼다. 칩을 누르면 해당 사건을 선택한다.
- AI 요약은 최신 1개만 한 줄로 보여 주고 펼쳐서 나머지를 본다. 동기화 누락 경고는 유지한다.

### 글 보관함

- 커버 카드 격자 대신 행 목록(제목·첫 문단 한 줄·상태 배지·수정 시각·삭제)을 쓴다.
- 상태 필터(전체·내 보관함·Ghost 초안·공개·편집 완료)와 제목 검색을 한 줄에 둔다.

### 연결과 데이터 / 관리자

- 기기·사용자·작업·모델 호출처럼 계속 쌓이는 목록은 4개 또는 8개만 보여 주고 "n개 더 보기"로 펼친다.

- 카드 안쪽 여백을 26px에서 20px로, 입력 높이를 44px에서 34px로 줄인다. 계정 카드와 데이터 카드를 "계정과 데이터" 하나로 합친다.
- 관리자: 통계 3개와 완성 비율 카드를 통계 띠 하나로 합치고, 표 행 높이를 줄인다.

### 글 에디터

- 전역 사이드바가 없어져 본문 영역이 넓어진다(왼쪽 240 / 본문 / 오른쪽 300).
- 상단바와 서식 도구 막대 높이를 줄이고, 원본 사건 목록을 52px 카드에서 32px 행으로 바꾼다.
- 버튼 이름("편집 완료", "버전", "Markdown", "미리보기", "Ghost 초안", "공개하기")은 유지한다.

## 5. 유지할 계약

- 버튼·라벨 이름: `작업 공간 열기`, `샘플로 둘러보기`, `초안 만들기`, `관리자`, `글 보관함`, `메뉴 열기`, `미리보기`, `Markdown`, `버전`, `편집 완료(됨)`, `Ghost 초안`, `닫기`, `글 제목`, `글 본문` 등.
- 대시보드 제목 `오늘의 풀이가…`, 관리자 제목 `운영 현황`, 글 제목의 heading 역할, `.file-tabs button.active`의 파일명 텍스트.
- 세션·파일 딥링크(`/?session=&file=`), 작업 SSE·폴링, 자동 저장·충돌 복구 동작.

## 6. 검증

- `pnpm --filter @autoblogger/web typecheck`, 웹 production build, vitest.
- Playwright e2e(AI 비용이 없는 시나리오): workspace, editor-conflicts, extension-link.
- 1440×900, 1024×768, 390×844 화면 캡처로 높이와 가로 스크롤 여부를 확인한다.

## 7. 결과

같은 데이터(샘플 프로젝트 1개·사건 6개·글 1개, 기기 7개 이상)로 콘텐츠 실제 높이(하단 바닥글까지)를 측정했다. 개편 전 값은 기존 코드를 서빙하던 dev 서버에서 측정했다. 타임라인은 AI 요약 영역을 뺀 높이다(개편 전 요약 158px, 개편 후 요약 띠 약 85px).

| 화면 | 1440×900 전 → 후 | 390×844 전 → 후 |
| --- | --- | --- |
| 대시보드 | 1212 → 471 | 1117 → 777 |
| 풀이 기록 | 529 → 268 | 526 → 324 |
| 프로젝트 상세 | 659 → 390 | 651 → 446 |
| 세션 타임라인 | 1407 → 524 | 1541 → 580 (사건을 펼치면 상세 높이만큼 늘어남) |
| 글 보관함 | 673 → 310 | 631 → 400 |
| 연결과 데이터 | 1275 → 925 | 2112 → 1508 |

- 1440×900에서 대시보드·풀이 기록·프로젝트·타임라인·글 보관함·에디터가 한 화면 안에 들어온다. 1024×768, 390×844에서도 가로 스크롤이 없다.
- 타임라인 사건은 행당 38px이다. 개편 전에는 펼쳐진 실행 사건 하나가 약 260px이었다.

### 계획에서 달라진 점

- 메뉴 접힘 기준을 860px에서 960px로, 타임라인 두 열 기준을 1000px로 정했다. 관리자 메뉴와 긴 작업 이름이 함께 있을 때 겹치지 않는 폭이다.
- 검증 중 기존 결함을 고쳤다. 자동 저장이 진행 중일 때 미리보기·Markdown·발행·제안 버튼을 누르면 `save()`가 조용히 false를 돌려 아무 반응이 없었다. 이제 진행 중인 저장을 기다린 뒤 그 사이 입력까지 저장하고 이어서 실행한다.

### 검증

- 웹 타입 검사, 웹 단위 테스트 12개 통과.
- 프로덕션 빌드: 사용자 dev 서버가 쓰는 `.next`와 겹치지 않도록 Linux 파일시스템의 복사본에서 `next build --webpack`으로 컴파일·타입·정적 페이지 생성을 통과했다. 복사본은 `node_modules`가 심볼릭 링크라 Turbopack 빌드는 실행할 수 없었다. CI의 `pnpm build`(Turbopack)는 아직 실행하지 않았다.
- Playwright 15개 통과: 기존 workspace·editor-conflicts·extension-link 12개와 새 `ui-layout.spec.ts` 3개(두 열 타임라인과 키보드 이동, 좁은 화면 펼침과 가로 스크롤 없음, 글 상태 필터와 제목 열기). `AUTO_SUMMARIES=false`, AI·Ghost 키를 비운 격리 API와 별도 데이터 디렉터리에서 실행했고 유료 호출은 없었다.
- 알려진 간헐 실패: API를 새로 띄운 직후 첫 미리보기 요청은 `@autoblogger/ai`를 동적 import한다. `/mnt/c`에서 tsx가 이를 컴파일하는 10초 남짓 동안 API 전체가 응답하지 않아 `editor saves, previews…`가 10초 제한에 걸린다. 워밍업 뒤 반복 실행과 전체 실행은 통과했다. UI 변경과는 무관한 API 기동 특성이다.
- 캡처 검토 중 고친 것: 대시보드 두 패널의 세로 어긋남, 한국어 음절 단위 줄바꿈(`word-break: keep-all`), 모바일 작업 버튼 아이콘이 함께 숨던 선택자.
